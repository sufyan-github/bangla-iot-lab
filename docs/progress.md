**Browser tests and a busy computer.** Some tests wait for something the
simulation does (a servo sweep, a sensor reading, two boards talking). On a
busy computer the simulation runs slower than real time, and a wall-clock
limit could run out. Since 24 November 2026 those tests wait in the lab's own
time instead (D-091): they keep trying until the lab has run long enough, with
a hard limit of three minutes of real time. Waits for a compile are still
wall-clock limits, as a compile does not run in lab time. Earlier causes,
removed on 22 November 2026: the phone-sized code editor sometimes kept the old
program (tests now check what they typed), and the API's compile limit (the
tests' own API allows more).
